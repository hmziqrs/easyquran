# Hard rules:
- Quran databases are all immutable. No modifications and never versioning.
- **`db/` is untracked and gitignored.** The Quran DBs live in R2 (`easyquran` bucket) and are provisioned onto disk out of band; they are never committed, never added back with `git add -f`. Anything that must survive a fresh clone cannot live under `db/`.
- No SHA-256 over Quran data in any automated path (build, boot, runtime, ETag, cache, catalogue). A DB's identity is its **id**, never a hash. SHA-256 is manual audit only — three commands a human runs: `just quran-audit`, `pnpm audit:arabic`, `pnpm verify` (in `db/quran/translations`). Crypto sha (CSRF, HMAC, Argon2, PKCE) is unrelated and stays. Don't re-add Quran sha — guards in `tests/quran_v1.rs` + `web catalogue-sha-guard.test.ts` fail the build (see docs/quran-system.md — Hard rules).
- Always load and follow the `caveman` skill at the beginning of every session. Keep Caveman full mode active for every response. This rule is also applied to subagents.
- Reader navigation hrefs must preserve translation context: use the `surah*For(ctx,...)` family in `web/src/lib/data/quran.ts` (`surahPathFor`/`surahLocalPagePathFor`/`surahAyahPathFor`/`globalPagePathFor`/`juzPathFor`) with `ctx` from `surahRouteContext(sourceId)` or `routeContextFromParams(page.params)`. Never call the Arabic-only `surahPath`/`surahLocalPagePath`/`surahAyahPath` from a component, and never hand-build `/app/` URL strings. Machine-guarded by `web/src/routes/(application)/app/__tests__/nav-guard.test.ts` (`pnpm test`).
- Delivery divergences from `docs/my-plan-raw.md`: translated reader routes (`/app/t/**` and `/app/[surah]/t/**`) are SSR + 7-day disk cache — never SSG; prerender stays Arabic-only, and production Quran bytes/size/path come from baked id maps, never remote metadata. Full record: `docs/quran-system.md` Part 5 (Divergences from `my-plan-raw.md`).
- **No nested ternaries.** A `?:` may never appear inside another `?:` — not in either branch, not in a `$derived`, not in JSX/markup expressions, not in tests or `scripts/`. Use a named function with early-return `if`s (`function packLabel(): string { if (busy) return "…"; … }`), a lookup table (`XML_ENTITIES[c]`), or a first-match helper (`firstString(o, "last_seen", "lastSeenAt")`). A single flat ternary is fine. Machine-guarded by `pnpm lint`.
- **Lint rules live in `web/vite.config.ts` → `lint.rules`** (`vp lint`/`vp check` read oxlint settings from that block; see https://viteplus.dev/config/lint). Rules there *extend* oxlint's defaults. Never add a standalone `.oxlintrc.json` — it is not auto-discovered by `vp lint`, and when passed via `-c` it *replaces* the default rule set, silently dropping ~30 other checks. Currently enforced beyond the defaults: `no-nested-ternary`, `unicorn/no-nested-ternary`, `no-shadow`, `prefer-promise-reject-errors`, `unicorn/no-array-callback-reference`, `unicorn/prefer-number-properties`, `no-floating-promises`, `no-misused-promises`.
- **All three gates are green and must stay green: `pnpm check`, `pnpm lint`, `pnpm test`.** `pnpm lint` runs with `--deny-warnings`, so a warning is a failure.
- **`pnpm check` is warning-free and must stay that way** — `svelte-check` runs with `--fail-on-warnings`, so an a11y or Svelte compiler warning fails the build. Never relax the flag to land a warning: fix the markup, or add a scoped `<!-- svelte-ignore rule_name -->` with a comment saying why the exception is correct. `tsconfig.json` also sets `noUncheckedIndexedAccess`, `noImplicitOverride`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `noUnusedLocals`, `noUnusedParameters` on top of `strict`.
- Prefer **es-toolkit** (`import { clamp } from "es-toolkit"` — named imports only, never `import * as`) over hand-rolling `clamp`/`groupBy`/`uniq`/`sumBy`-style utilities. It is `sideEffects: false` + ESM, so Vite tree-shakes per-function with no extra config. Check the real semantics before swapping — they are not always what the name implies: `inRange(v, min, max)` is **max-exclusive** and does no integer check, so it is NOT a drop-in for an inclusive `n >= 1 && n <= 114` bound, and 1-arg `clamp(v, max)` means *maximum*, not minimum. Keep the existing `trailingDebounce` (`$lib/storage`); do not swap it for es-toolkit `debounce`.
- All web keyboard shortcuts (cmdk, reader nav, any key-based action) use **TanStack Hotkeys** (`@tanstack/hotkeys`, pinned `0.8.0` — alpha) via the shared wrapper `web/src/lib/hotkeys.svelte.ts` (`registerHotkey()` over the `HotkeyManager` singleton). Never hand-roll `keydown`/`addEventListener`/`metaKey`/`isPaletteChord`-style handlers for app shortcuts. The library MUST be dynamically imported (`await import("$lib/hotkeys.svelte")`) from its consumer — never statically imported into an always-mounted component — so it stays out of the initial bundle. Gotcha: TanStack does not guard IME composition; any shortcut clashing with an IME session keeps its own `event.isComposing` early-return. Register from a client-only Svelte `$effect`, `unregister()` on cleanup.

# Dynamic context loading
Load relevant context ONLY when working on that area:

- **Rust backend** (`rust/backend/api/`): load `rust/backend/api/AGENTS.md` + `rust/backend/api/README.md` if exists.
- **Web** (`web/`): load `web/README.md` + Svelte skills (`svelte-core-bestpractices`, `svelte-code-writer`).
- **DB/migrations**: load `rust/backend/api/migration/README.md`.
- **Deploy**: load `deploy/README.md`.

Do NOT preload all context every session. Load on-demand based on files touched.

Always commit to the current branch unless I say otherwise.
