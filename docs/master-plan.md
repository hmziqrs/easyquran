# Master plan — execution registry

The phase-ordered index for every hot plan in `docs/`. Each phase carries a status, what gates it,
a definition of done, the next concrete action, and the doc that owns the design. Sub-plans point
back here via a "Sequenced by" line near their status; this file is the only place execution order
lives. Nothing here changes a design — the owning docs stay authoritative.

**Status vocabulary.** `ready` — nothing hard-gates it; `backlog` — waiting on its `Depends on`;
`gated` — behind a named decision gate; `retired` — distilled into `documentation/` and removed.
If a sub-plan's own status line disagrees with this registry, the registry wins and the sub-plan
should be fixed to match.

**Canonical order: V → A1 → A2…A19 → P → R**, with **U** slotted alongside any of the A-phases
when capacity allows (it is independent of all of them). Order is execution priority, not
dependency: the `Depends on` column is the only hard gate, and a `ready` phase may start whenever
the queue reaches it.

## Rules

- **Retirement.** When a phase's definition of done is met, the owner distils a permanent record
  into `documentation/` **by hand** (agents never create, edit, move, or delete anything there),
  then the hot doc is deleted or archived. See [`README.md`](README.md).
- **Frozen inputs.** [`next-features.md`](next-features.md) takes zero edits until V's single
  correction pass (its bookmark/session/analytics briefs were cut 2026-10-14 by owner direction —
  [`reading-model.md`](reading-model.md) replaces them). [`docs/research/**`](research/) is raw evidence — cited, never rewritten.
- **Design authority is unchanged.** [`abuse-prevention.md`](abuse-prevention.md) §12 stays the
  design-level dependency table for the A-phases; this registry tracks execution status only.
